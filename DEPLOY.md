# Deploying Eventura

Target setup: **Vercel** (frontend) + **Render** (backend API, Docker) + **PlanetScale** (MySQL-compatible database). None of these steps can be done on your behalf — each needs your own account/login — so this is a checklist to follow in your own browser. Total cost: **$0** on each platform's free tier (Render's free web service does sleep after 15 minutes of inactivity and cold-starts on the next request — fine for a demo/portfolio project).

Do the steps **in this order**, since the backend and frontend each need to know the other's URL.

## 1. Database — PlanetScale

1. Sign up free at https://planetscale.com and create an organization.
2. **Create a database** named `eventura` (any region close to your Render region).
3. Once it's provisioned, go to **Connect** → pick **General / Go** → copy the connection details: `host`, `username`, `password`. The database name is `eventura` (or whatever you named it).
4. Leave this tab open — you'll paste these into Render next.

> PlanetScale requires TLS and doesn't need foreign-key constraints — the backend is already configured for both (`DB_SSL=true`, `DisableForeignKeyConstraintWhenMigrating`), so no code changes are needed here.

## 2. Backend API — Render

1. Sign up free at https://render.com and connect your GitHub account.
2. **New +** → **Blueprint** → select the `dhavisiregar/eventura` repo. Render will detect `render.yaml` at the repo root and propose one service: `eventura-backend`.
3. Before clicking **Apply**, you'll be prompted for the env vars marked `sync: false` in the blueprint — fill in:
   - `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` → from PlanetScale (step 1.3)
   - `MIDTRANS_SERVER_KEY`, `MIDTRANS_CLIENT_KEY` → from https://dashboard.sandbox.midtrans.com/settings/config_info
   - `FRONTEND_URL` → leave as a placeholder for now (e.g. `http://localhost:3000`); you'll update it in step 4
   - `JWT_SECRET` is auto-generated by Render — you don't need to set it, just **copy its value** afterward (Render dashboard → eventura-backend → Environment) since the frontend needs the exact same value.
4. Click **Apply**. Wait for the first deploy to finish, then open the service URL Render gives you (e.g. `https://eventura-backend.onrender.com`) and confirm `/health` returns `{"status":"ok"}`.

   If you'd rather not use the Blueprint, create the service manually instead: **New +** → **Web Service** → this repo → Runtime: **Docker**, Root Directory: `backend`, and set the same env vars listed in `render.yaml`.

> **Uploads on the free plan are ephemeral** — banner images stored in `/app/uploads` are wiped on every redeploy/restart, since persistent disks require a paid Render instance. Fine for testing; if you need banners to survive redeploys, either upgrade the Render instance and add a disk (`render.yaml` → add a `disk:` block mounted at `/app/uploads`), or swap the upload handler for an external store (S3/Cloudinary) later.

## 3. Frontend — Vercel

1. Sign up free at https://vercel.com and connect GitHub.
2. **Add New** → **Project** → select the `dhavisiregar/eventura` repo.
3. In the import screen, set **Root Directory** to `frontend` (click Edit next to Root Directory).
4. Add these **Environment Variables** (Production — and Preview/Development too, if you want):
   - `NEXT_PUBLIC_API_URL` = `https://<your-render-backend>.onrender.com/api/v1`
   - `NEXT_PUBLIC_UPLOADS_URL` = `https://<your-render-backend>.onrender.com`
   - `JWT_SECRET` = the exact same value as the backend's `JWT_SECRET` (from Render step 2.3/4)
5. Click **Deploy**. Once it's live, note your Vercel URL (e.g. `https://eventura-yourname.vercel.app`).

## 4. Close the loop: point the backend at the real frontend URL

1. Back in Render → `eventura-backend` → **Environment** → set `FRONTEND_URL` to your real Vercel URL from step 3.5.
2. Save — Render redeploys automatically. This is what makes CORS and the post-payment Midtrans redirect (`/checkout/return`) point at the right place in production.

## 5. Verify end-to-end

- Open your Vercel URL, register a customer and an organizer account.
- As the organizer, create a free event and confirm it shows up on the landing page.
- As the customer, book the free event and confirm it appears under **My tickets**.
- For a paid event: complete a sandbox payment via Midtrans's simulator. You should land back on `/checkout/return` on your **Vercel** domain (not `example.com`), which confirms `FRONTEND_URL` is wired correctly.

## Optional: a real Midtrans webhook (recommended for anything beyond a demo)

Locally, the app relies on the client-side `/transactions/sync/:orderID` call (since Midtrans's servers can't reach `localhost`). In production, Render's backend *is* publicly reachable, so you can additionally register the real webhook for reliability (e.g. if a user closes the tab before the redirect fires):

1. Midtrans sandbox dashboard → **Settings → Configuration**.
2. Set **Payment Notification URL** to `https://<your-render-backend>.onrender.com/api/v1/midtrans/notification`.

No code or redeploy needed — that endpoint already exists and verifies Midtrans's signature.
